## 3. Basemap labels

Done within the time limit; it needed only a style expression. OpenFreeMap's OpenMapTiles tiles carry `name:pt` and `name:en`. I checked the rendered features: Sevilla → "Sevilha" / "Seville", España → "Espanha" / "Spain", Lisboa → "Lisboa" / "Lisbon".

Both themes use the same name expression, on 16 positron layers and 12 Dark Matter layers. Each of those layers now shows:

```
PT: ["coalesce", ["get","name:pt"], ["case", ["has","name:nonlatin"], ["get","name:latin"], ["get","name"]]]
EN: ["coalesce", ["get","name:en"], ["case", ["has","name:nonlatin"], ["get","name:latin"], ["coalesce", ["get","name_en"], ["get","name"]]]]
```

- **Fallback:** it is the previous Latin-only expression, so a place without a name in the language looks as before. Moroccan names still request no Arabic or Tifinagh glyphs: the glyph e2e test now runs in both languages and passes.
- **EN:** unchanged in practice; it already showed `name_en`.
- **How it's applied:** at load and on a theme switch through `basemapStyle(theme, lang)`. On a language switch, `setLabelLanguage` calls `setLayoutProperty` on those layers, so the style isn't reloaded and the camera doesn't move.
- **Code:** `web/src/basemap.ts` (`labelField`, `setLabelLanguage`) and `main.ts`.
