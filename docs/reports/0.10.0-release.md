# 0.10.0 release: land check and the Pi source watcher (2026-11-15)

Live at https://pnct.singledev.eu. Release commit `e853f80`, annotated tag `v0.10.0`, both pushed.

## 1. Accessibility (commit 8b0e3bb)
- **Keyboard toast:** the first time the map gets keyboard focus in "Check a spot" mode, a toast says "Enter checks the centre · Esc exits" (PT "Enter verifica o centro · Esc sai"). It shows once per session.
  - A key pressed on a map focused by a mouse click counts too, since Chrome doesn't fire a second `focus` event there.
  - Touch and mouse behaviour is unchanged.
- **Screen readers:** each check is announced once, e.g. "PNCT: yes. Hazard: Very high. França". The text is the same as the peek row and the report heading, and it's sent once the hazard value has loaded.
  - It goes through one persistent `role="status"` / `aria-live="polite"` region (`#check-live`), not the peek or the heading themselves. Those are rebuilt on every render, so as live regions they would either repeat or stay silent.
  - The panel itself is `aria-live="off"` while it shows a check, so it isn't read twice. It goes back to `polite` for parish and concelho panels.
  - A language switch re-renders the report without announcing it again.
- **Tests:** 5 new e2e tests:
  - the keyboard toast once per session, also after a reload;
  - no keyboard toast for mouse focus;
  - keys on a mouse-focused map;
  - the toast in PT;
  - one announcement per check, none on a re-render (counted with a MutationObserver), a new check announced again, and parish panels live again.

  The touch test also checks the announcement. The glossary has the new term.

## 3. Source watcher rebase, monthly SHA check, merge
- **Rebase:** `feat/pi-source-watcher` (6 commits) went onto the new `main` with **no conflicts**. The watcher's additions to `scripts/landcheck_config.py` (`BlockedFact`, `Watch`, the watched endpoints) were applied on top of main's land check code without changes.
- **Monthly forced SHA-256 check** (commit 6fd5c54):
  - Every `FORCE_SHA_DAYS` = 28 days (every 4th weekly run), the ICNF zip is downloaded and hashed even if size, ETag and Last-Modified haven't changed. The time of the last full check is stored as `verified_at` in the state.
  - A silent same-size replacement is reported within a month. The message adds "Found by the monthly full check: size, ETag and Last-Modified were unchanged."
  - A forced download that fails is reported as an outage, not as a change, and the last known values are kept.
- **3 new tests** on the recorded HEAD (`tests/fixtures/watcher/hazard_head.json`):
  - the 4-week cadence, and the clock restarting afterwards;
  - the silent replacement caught in week 4 and reported once;
  - a failed forced download and its recovery.

  With the forced check disabled, all 3 fail. README and the watcher report are updated.
- Full suite: pytest 181, Vitest 255, e2e 182 passed, none flaky.
- `main` fast-forwarded from 8b0e3bb to 6fd5c54.

## Pi setup (from ops/pi/README.md)

```sh
# 1. A checkout readable by the service user (the default path needs no drop-in).
sudo git clone https://github.com/singledev-eu/pnct-map.git /opt/pnct-map

# 2. Install: user, packages if missing, /etc/pnct/pi.env, state dir, units.
sudo /opt/pnct-map/ops/pi/install.sh

# 3. Fill in the token and chat id (a separate @BotFather bot, or Prazo's token), then run install again.
sudo nano /etc/pnct/pi.env
sudo /opt/pnct-map/ops/pi/install.sh        # checks the units, enables the timer, shows the next run

# 4. Prove it.
sudo /usr/bin/python3 /opt/pnct-map/ops/pi/source_watcher.py --test-message --env-file /etc/pnct/pi.env
sudo systemctl start pnct-source-watcher.service   # the baseline run, one message
```

Telegram chat id: send your bot any message, open `https://api.telegram.org/bot<token>/getUpdates`, and copy `message.chat.id`. To update later: `cd /opt/pnct-map && sudo git pull && sudo ops/pi/install.sh`.
