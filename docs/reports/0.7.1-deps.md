## Pipeline: byte-identical

I ran `make clean && uv run make all` (7 min; the downloads were reused). Every output is byte-identical to before: `data/interim`, all of `data/processed`, and all of `web/data` (`pnct.topo.json`, `shapes.json`, `outline.json`, the protected-area files, `concelhos.json`). pytest passed (114).

One diff, reverted:
- **What changed:** the RNAP `as_of`/`fetched_at` dates in `protected.meta.json` and `protection.json` (4 fields).
- **Why:** make re-fetched RNAP from ICNF because `scripts/protected_config.py` (19 Oct) is newer than the old fetch marker (17 Oct). The upgrade had nothing to do with it.
- **The fetched data:** identical; the shares and geometry didn't change.
- **Action:** I reverted the two files so the data still shows the 0.7.0 dates.

`make clean` also deletes the untracked `data/interim/contacts/` batches (local curation files). I backed them up first and restored them.

## Production build: unchanged

`dist/` built before and after the bump is **byte-identical**: the same hashed filenames, e.g. `index-CIJTuum3.js` (1,114,503 B). The bundle size diff is 0. Production serves that same `index-CIJTuum3.js`.

## Dependabot

- **Alerts:** 50 open before (Pillow 41, certifi 1, vite 6, @vitest/mocker 2). These are per advisory; the 0.7.0 push summary said 14.
- After the merge: **0 open**. The API lists 56 as fixed, which includes 6 earlier vite entries.
- The push message still said "50 vulnerabilities" from GitHub's earlier scan. The alerts API showed 0 after the deploy.
- **Version updates:** they weren't on (there was no `.github/`). `.github/dependabot.yml` now asks for weekly PRs:
  - `npm-dev`: every development dependency in `/web`, grouped;
  - `uv`: every Python dependency, grouped.

  The runtime npm dependencies (maplibre-gl, topojson-client) get their own PRs on purpose: a MapLibre bump changes what the site ships.
- **Dependabot security updates** (automatic fix PRs for alerts) are still **disabled** in the repo settings. That wasn't asked for, so I left it as is.
